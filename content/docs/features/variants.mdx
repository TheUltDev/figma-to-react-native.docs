# Variants

Component variants allow you to create multiple states or versions of a component within a single Figma component set. When exported to React Native, these variants become props that control the component's appearance and behavior.

<img src="https://placehold.co/800x400/2563eb/ffffff?text=Figma+Component+Variants" alt="Figma Component Variants Overview" />

## What Are Variants?

Variants are different states or configurations of a component that share the same base structure but have different visual properties. Common use cases include:

- **Button states**: Default, pressed, disabled, loading
- **Card types**: Basic, featured, premium
- **Icon sizes**: Small, medium, large
- **Theme variations**: Light, dark, colored

## Creating Variants in Figma

### 1. Create a Component Set

Start by creating individual components for each variant, then combine them into a component set:

1. Create your base component
2. Right-click and select "Create component set"
3. Add additional variants by duplicating or creating new components within the set

<img src="https://placehold.co/600x300/059669/ffffff?text=Creating+Component+Set" alt="Creating Component Set in Figma" />

### 2. Define Variant Properties

Each variant can have multiple properties with different values:

```
Button Component Set:
├── State = Default, Pressed, Disabled
├── Size = Small, Medium, Large
└── Type = Primary, Secondary, Ghost
```

<img src="https://placehold.co/600x350/7c3aed/ffffff?text=Variant+Properties+Panel" alt="Variant Properties Panel" />

### 3. Configure Variant Combinations

Each unique combination of properties creates a specific variant:

- `State=Default, Size=Medium, Type=Primary`
- `State=Pressed, Size=Large, Type=Secondary`
- `State=Disabled, Size=Small, Type=Ghost`

## Generated TypeScript Types

The plugin automatically generates TypeScript types for your variants:

```typescript
// Generated variant types
export const ButtonVariants = {
  state: ['Default', 'Pressed', 'Disabled'] as const,
  size: ['Small', 'Medium', 'Large'] as const,
  type: ['Primary', 'Secondary', 'Ghost'] as const,
}

// Component props interface
interface ButtonProps {
  state?: typeof ButtonVariants.state[number];
  size?: typeof ButtonVariants.size[number];
  type?: typeof ButtonVariants.type[number];
  // ... other props
}
```

## Using Variants in Components

### Basic Usage

The generated component uses the `useVariants` hook to manage variant styles:

```typescript
import { useVariants } from '@kattax/exo';

export function Button({ state, size, type, ...props }: ButtonProps) {
  const { root } = useStyles(stylesheet);
  const { vstyles } = useVariants(ButtonVariants, { state, size, type }, styles);

  return (
    <Pressable style={[root, vstyles.root]} {...props}>
      {/* Component content */}
    </Pressable>
  );
}
```

### Advanced Variant Handling

For complex components with nested variant styles:

```typescript
export function Card({ variant, size, theme, ...props }: CardProps) {
  const { root, header, content, footer } = useStyles(stylesheet);
  const { vstyles } = useVariants(CardVariants, { variant, size, theme }, styles);

  return (
    <View style={[root, vstyles.root]}>
      <View style={[header, vstyles.header]}>
        {/* Header content */}
      </View>
      <View style={[content, vstyles.content]}>
        {/* Main content */}
      </View>
      <View style={[footer, vstyles.footer]}>
        {/* Footer content */}
      </View>
    </View>
  );
}
```

## Best Practices

### 1. Naming Conventions

Use clear, descriptive names for your variant properties:

```
✅ Good:
- State: Default, Pressed, Disabled
- Size: Small, Medium, Large
- Type: Primary, Secondary, Ghost

❌ Avoid:
- Property 1: Value 1, Value 2
- Var: A, B, C
```

### 2. Logical Grouping

Group related properties together:

```typescript
// Button variants
state: ['default', 'pressed', 'disabled']
size: ['small', 'medium', 'large']
type: ['primary', 'secondary', 'ghost']

// Card variants
variant: ['basic', 'featured', 'premium']
layout: ['horizontal', 'vertical']
theme: ['light', 'dark']
```

### 3. Default Values

Always provide sensible defaults:

```typescript
export function Button({
  state = 'default',
  size = 'medium',
  type = 'primary',
  ...props
}: ButtonProps) {
  // Component implementation
}
```

### 4. Performance Considerations

- Keep the number of variants reasonable (avoid exponential combinations)
- Use semantic naming for better tree-shaking
- Consider breaking complex variants into separate components

## Troubleshooting

### Common Issues

1. **Variant not applying**: Check that variant properties are correctly named and match the component set
2. **Missing styles**: Ensure all variant combinations have proper styling in Figma
3. **Type errors**: Verify that the generated TypeScript types match your usage

### Debug Tips

```typescript
// Debug variant resolution
const { vstyles } = useVariants(ButtonVariants, props, styles);
console.log('Applied variants:', vstyles);

// Check variant props
console.log('Variant props:', { state, size, type });
```

<Callout type="info">
Variants are processed during the component generation phase. Changes to variant properties in Figma require re-exporting the component.
</Callout>

## Advanced Features

### Conditional Variants

Some variants may only apply under certain conditions:

```typescript
// Only show loading state when actually loading
const effectiveState = isLoading ? 'loading' : state;
const { vstyles } = useVariants(ButtonVariants, { state: effectiveState, size, type }, styles);
```

### Nested Variant Components

Complex components may have nested elements with their own variants:

```typescript
export function ComplexCard({ variant, size, ...props }: ComplexCardProps) {
  const { vstyles } = useVariants(CardVariants, { variant, size }, styles);

  return (
    <View style={[styles.root, vstyles.root]}>
      <CardHeader variant={variant} size={size} />
      <CardContent variant={variant} />
      <CardFooter variant={variant} size={size} />
    </View>
  );
}
```
